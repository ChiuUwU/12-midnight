# 管理员档案配置与限制

> 文档定位：管理员功能的配置与安全验收说明；记录敏感信息的功能只有在真实环境配置、部署并验证后才能视为可用，当前状态见 [这里](./current-status.md)。

管理员入口可以读取进行中和已结束对局的敏感身份、夜间行动及票型。Pages Functions 只在设置了至少 12 字符的 `ADMIN_PASSWORD` 加密 Secret 后允许登录；密码不得写入 Git、前端代码或对话。未配置时接口返回不可用。通过密码登录后使用 30 分钟的 HttpOnly、Secure、SameSite=Strict 会话；同一来源五分钟最多尝试五次。

上线前由项目所有者在 Cloudflare Pages 项目的 Settings → Variables and Secrets 中新增名为 `ADMIN_PASSWORD` 的 Secret，选择加密并保存；建议使用随机生成的 16～20 位以上强密码，不要覆盖已有变量或其他绑定。按 Cloudflare 的配置要求重新部署，并在 HTTPS 生产环境验证未登录请求无法读取档案、错误密码被拒绝、正确密码只能由授权人员使用。不要在对话中发送密码。

Cloudflare Pages 使用已有 `DB` D1 绑定；新代码创建 `game_archives` 和 `admin_login_attempts` 表，不删除或覆盖现有表。发牌后每次房间状态更新会通过条件写入同步更新该局档案，包含身份、夜间行动、死亡、已完成票型和事件；不保存房间法官口令、控制令牌或设备标识。进行中的投票仅限管理员查看。档案没有自动清理策略，需要关注 D1 容量和项目的数据保留/备份策略。

房间仍按原规则过期；新增档案不是数据库备份。上线前已经过期且未单独归档的夜间行动通常无法从现有胜负记录中恢复。启用后旧房间若仍存在，只有在后续产生状态更新时才会创建快照；不会自动恢复丢失的数据。

本地 `node server.js` 不提供 D1 管理员接口，管理员流程应在 Pages Functions 本地模拟或部署后的测试环境中验证；不要将未配置或未经验收的管理接口视为已上线。
