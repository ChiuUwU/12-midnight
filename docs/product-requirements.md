# 最后一夜 Last-Night：产品需求说明

状态：产品基线与需求索引；最后整理于 2026-10-31。本文描述产品目标和已讨论的方向，并不代表所有功能均已实现、上线或完成验收。具体实现状态见 [当前状态](./current-status.md)，具体版型规则以对应规则源文档为准。

## 1. 产品定位

为线下狼人杀聚会提供手机优先的网页工具，减少发牌和法官记录的负担，并支持由玩家设备与公共控制设备配合主持对局。游戏主要在线下进行，网页为身份、流程与规则提供辅助。

## 2. 用户与场景

- 组局者：选择版型和模式，创建房间，组织玩家入座与开始游戏。
- 法官：在有法官模式下查看必要的完整信息，依据面板提示主持、记录和修正操作。
- 玩家：加入对应座位、私密查看身份；在无法官模式中按自身权限提交行动与投票。
- 控制设备：在无法官模式中负责公共流程、播报和控制，不应获得法官式全局身份视图。
- 管理员：经认证后查看对局档案，包括进行中的敏感信息；配置、安全控制和生产验收见 [管理员说明](./admin-setup.md)。

## 3. 产品模式

### 有法官模式

网站是法官的辅助工具：展示身份和夜间流程、记录行动、辅助计算并提示结算；由法官按线下进程主持。白天区分警上和警下，允许不录逐人票型，但需要记录夜间死亡信息和白天放逐结果或无人出局，并处理必要的技能窗口。

### 无法官模式

玩家在手机上执行授权的夜间和白天操作；系统负责计算并公布结果，公共控制设备负责播报。普通版型可手机投票，也可线下投票后由控制设备录入；暗黑破坏的投票和迷雾权限另见对应版型文档。固定夜间时长、播报可靠性和所有出局询问的统一流程仍在开发，不应以本文作为实现完成证明。

## 5. 关键产品原则

1. 隐私与权限由服务端校验；玩家和无法官控制设备不得获取不应知道的身份或行动信息。
2. 所有模式应维持已确认的公共流程，不能通过省略步骤泄露身份或存活状态；有法官界面可私密说明不可行动原因。
3. 常见公共机制优先抽成可复用能力，包括夜间目标映射、白天即时技能窗口、私密信息及死亡记录。
4. 游戏规则的修改须先获得确认；网页文案或文档整理不能改变游戏规则。
5. 各环境数据寿命不同；线上档案不自动等同数据库备份或所有历史房间均可恢复。

## 6. 目标验收与待办

- 有法官：完成各版型真实浏览器整局检查，涵盖警上自爆、放逐、换号、撤回、死亡及连锁技能。
- 无法官：完成固定夜间步骤、已确认计时/加时和出局技能询问，再验证手机语音、锁屏、中断、重连、并发与隐私。
- 线上：核实 Git 提交、部署版本、Pages/D1 绑定、管理员权限和数据保留；生产配置与本地模拟分别验收。
- 视觉与规则：在竖屏设备确认首页与卡面，核验规则来源、生成页面和实际游戏逻辑的一致性。

需求实现计划及未完成边界见 [统一流程改造](./unified-flow-implementation.md) 和 [真实设备验收清单](./system-mode-acceptance-checklist-v1.0.md)。涉及版型细节的疑问应先确认，不通过产品文档擅自改规则。
