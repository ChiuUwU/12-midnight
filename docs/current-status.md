## 入座并发缺陷跟进（2026-10-27）

- 根因已复现：入座也使用整房间 `revision` 校验；任意玩家先入座都会使其他玩家基于旧快照的请求返回 409。Pages/D1 还会因整房间 CAS 保存竞争而发生第二层冲突。
- 本地修复：入座改为按服务端当前座位/阶段校验；不同座位不再因旧房间版本互相阻塞；Pages/D1 入座 CAS 冲突有限重试；客户端只接受不低于当前版本的轮询/提交响应，并屏蔽重复点击。争抢同一座位仍只允许一人成功，失败方会刷新房间状态。
- 自动回归：已新增 Node API 并发入座测试与 Pages Function + D1 CAS 模拟测试；当前代码仍需完整测试套件、PR 和 Pages 部署后再做真实浏览器确认。
- 已知独立限制：如果玩家清除站点数据或换浏览器，设备身份会变化，旧座位可能显示占用但原设备无法认领。自动释放/认领会影响防抢座权限，未在本次修复中擅自增加。

## 已确认的后续开发标准

- 新版型优先复用能力而非增加专用分支。通用夜间目标映射、白天即时技能窗口、私密信息与死亡记录机制已进入首版实现；临时技能来源的通用建模及更多角色接入仍待后续。详细边界见 [`rule-data-structure-v0.1.md`](./rule-data-structure-v0.1.md) 的“8.5 先能力、后版型的开发标准”。
- 真实多设备验收完成前，不启动会重构白天流程或扩大夜间结算面的高风险版型实现。

## 白天流程与撤回修正（2026-10-30）

- 有法官白天界面分为醒目的“警上”和“警下 / 天亮与白天流程”两区。用户已确认夜间死亡结果和白天放逐结果必须记录，平安夜或无人出局也需确认；上警、退水、警徽和逐人票型可不记录。
- “进入下一夜”在白天始终显示且保持可点击；服务端按实际阻塞项拒绝过早推进并返回具体原因。未结束的复活/死亡结算、暗黑私密投票、延迟死亡、死亡技能或回溯重投仍不能略过。
- 无法官模式的白天可选技能窗口（定序王子回溯、天使长复活、狼王/猎人死亡技能）各自按顺序等待 5 秒；到时由联网客户端触发不发动并继续后续结算。此计时不作用于夜间必须行动的身份，也不能代替蒙面延迟死亡确认或未完成投票；所有设备离线或后台受限时，处理可能延迟至客户端恢复。
- 警长竞选自爆支持首次延期、延期竞选再自爆警徽流失，并提供不依赖竞选记录的“结束警上 / 进入警下”按钮。警上自爆先公布昨夜死讯再结算；同一狼人既自爆又夜亡时仍公布夜亡，但只按自爆进行出局技能结算。自动测试已覆盖两种模式中的同人场景，真实多设备验收仍待完成。
- 撤回夜间操作后，会移除最近一条已提交行动、重建当夜剩余步骤并恢复受该行动影响的动态状态；暗黑破坏的莉莉丝、莉娅举手、其他角色行动、莉娅充能/开雾仍处于同一有序夜间流程，不另起流程或重复播报已完成步骤。
- 自动回归覆盖撤回、白天必要记录、暗黑投票阻塞、竞选延期、警上自爆时的夜亡及 5 秒技能超时，并验证复活窗口结束后狼王获得新的 5 秒。真实浏览器/手机验收仍由产品负责人进行。
- 测试过程中曾两次出现本机测试服务 `fetch failed`，随后完整测试和多次单项复测通过；根因尚未确认，已增加测试错误诊断输出，不能据此认定线上连接问题已解决。
- 以上均为本地未发布工作区状态；没有推送、合并或部署。竖屏首页已在工作区调整为较短的桌面主视觉、并排房间入口和可展开版型规则列表；已做桌面浏览器窄视口截图，真实手机视觉与交互仍需验收。
