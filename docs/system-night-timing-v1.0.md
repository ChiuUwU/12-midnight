# 无法官夜间计时与提交验收（2026-11-03 确认）

本文是当前确认的计时要求，优先于旧文档中的统一 60 秒、额外改刀 10 秒、步骤间隔 10 秒等历史描述。不改变各版型技能效果或胜负规则。

| 假面、莉娅、盗宝大师第二夜起的私密带刀确认 | 各 30 秒，只向本人告知资格，不暴露队友座位 |
| 机械狼模仿夜、技能夜 | 各 60 秒，与普通狼刀独立 |

| 预言家查验、通灵师查验、女巫用药、守卫守护 | 各 60 秒 |

| 海妖选风、船长登船 | 各 60 秒 |

提前提交不提前结束公共等待，角色死亡、封技或技能耗尽也不缩短公共流程。最后十秒按原要求播报倒数。盗宝两段操作为同一计时窗口的私密子步骤，不因第二段出现而再次公开播报。

## 提交协议

- 使用具体房间、夜晚、步骤及撤回代际标识，而非仅用整个房间的 revision 判断夜间提交是否过期。
- 一次确认有独立请求 ID；快速重复点击合并成同一次请求，网络丢失响应后的相同内容重试复用 ID。
- 服务端按设备和请求 ID 返回首次成功的结果；不能用相同 ID 更换号码，也不能向其他设备泄露私密结果。药、牌、查验等不重复执行。
- 狼刀修改是新的明确确认操作，不属于重复请求；仍受同一截止时间约束。
- 撤回会作废本夜旧提交回执和步骤代际；旧页面、旧窗口、旧号码不能影响新步骤。
- 首夜必选等待不反复推进，不增加无意义业务版本；控制端确认玩家提交后才推进。
- 正常提交后明确显示已确认；轮询不清空当前仍有效选择，但步骤改变时必须清掉旧选择。

## 发布前必须按链路验收

不能用“测试总数通过”替代每一步骤证据。每次涉及房间同步/提交/计时的修改，至少检查：

1. 号码/牌/药物选择 → 经过轮询及心跳 → 确认成功。
2. 快速双击、两个并发相同请求、响应丢失重试：只生效一次、返回相同私密结果。
3. 已提交等待、必选超时继续等、到截止/加时/间隔边界：不无故刷新或提前结束。
4. 旧步骤、旧夜晚、撤回前的请求、篡改同一请求 ID、无权限设备：拒绝且不污染新步骤。
5. Node 与 Pages 分别验证；选牌、用药、查验、零目标确认及组合技能分别验证，不以混血儿代表全部身份。
6. 浏览器实际点击验证与真实手机语音、锁屏、断线验证分开记录；未验证不得标成通过。

测试映射：`tests/pages-seat-concurrency.test.js` 的双后端矩阵与技能变体、`tests/fixed-night-flow.test.js` 的时长边界、`tests/live-flow.test.js` 的前端请求保护。真实 Chrome 混血儿玩家链路在本地诊断目录 `analysis-output/night-submit-browser-20261103/`，模拟控制端保持在线，音频完成仍为模拟。

## 兼容边界

固定夜间流程只接受 `nightFlowVersion: 2`，不再为旧版本提供自动兼容或在线升级路径。Node 与 Pages API 对旧版无法官房间的写操作返回 409，提示新建房间；旧房间数据不会因此删除。新建联网房间自动标记版本 2。旧有直接 HTML 无法官房间仍不具备服务端计时、权限与并发保障。
